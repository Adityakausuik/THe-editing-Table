- Verify every collection name, index option, unique constraint, sparse index, TTL index, and reference against the live Mongo catalog.
- The local model audit found no index paths missing from schemas and no declared indexes on fields mapped to JSONB. The only declared TTL indexes are on `emailotps.expiresAt`, `sessions.expiresAt`, and `trusteddevices.expiresAt`.
- Confirm JSONB treatment of nested structures and arrays against actual consumers and query patterns.
- Profile orphaned references before creating foreign keys. Validate required fields and uniqueness against production records.
- Mongo TTL behavior is implemented for PostgreSQL with a daily Vercel Cron cleanup of expired OTPs, sessions, trusted devices, and chunk-upload sessions. The production project must set `CRON_SECRET` before enabling the PostgreSQL backend; until PostgreSQL is selected, the cron endpoint is a no-op.
- GridFS file bytes and upload chunks are not represented by the generated model schema; files need an independently verified object-storage migration.
- The generated SQL is not yet validated by a PostgreSQL server, and has not been applied anywhere. The JSON inventory reflects local Mongoose declarations, not live collection/index discovery.
- The repeatable migration script reads Mongo collections directly without calling the app's bootstrap hook; before any DDL/data write, it checks model-declared references for orphan counts, required values for missing/nulls, and source duplicates for declared unique indexes. It writes PostgreSQL batches with ID-preserving upserts and checkpoints, refuses target rows without a checkpoint, preserves top-level unknown fields in `mongo_migration_extras`, and compares source/target row counts. BSON 64-bit values that exceed JavaScript's safe integer range are preserved as Extended JSON in flexible fields and cause a hard failure in numeric columns rather than silently losing precision. Binary and Decimal128 unknown/flexible values are also retained in Extended JSON form. This path still requires integration testing against a disposable Mongo/PostgreSQL pair before use.
- Timestamp columns in the generated PostgreSQL schema are nullable so the importer can preserve legacy Mongo documents that lack `createdAt` or `updatedAt`; the importer already maps absent timestamps to SQL `NULL`.
- The PostgreSQL review repository implements public filtering/pagination/statistics, featured review reads, pending review submission, admin listing and stats, moderation, replies, edits, deletes, bulk actions, and CSV export.

6. For cutover, use a maintenance/read-only window or change-capture strategy to avoid missing writes. Switch production only after all critical paths pass. Keep Mongo and its backup intact for rollback; rollback means restore the Mongo-backed deployment/configuration, not delete PostgreSQL data.
